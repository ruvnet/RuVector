SIGNED ANCHORING ACCEPTANCE RESULT: REJECT

Root cause: at batch_size=1, the original RootSwap tamper computed
`other = (idx + 1) % roots.len()`, which for a 1-element batch is
`(idx + 1) % 1 == idx` -- a swap with itself, i.e. a no-op. All 100
RootSwap trials at batch_size=1 therefore left the batch honest, and the
verifier correctly verified it -- which the trial-counting code (looking
for verification failure) recorded as "tamper not detected." The other
two tamper kinds (SignatureByteFlip, ProofSiblingFlip) were unaffected;
ProofSiblingFlip was itself later found to be inapplicable at
batch_size=1 for an unrelated reason (no Merkle level exists for a
single-leaf batch) and is now skipped at that batch size rather than
silently miscounted -- see the README's Failure Modes section and
`apply_sign_tamper` / the `batch_len == 1` guard in
`crates/ruvector-retrieval-receipt/src/bin/benchmark.rs`.
