# ADR: Preserve current caller identity through HNSW replacements

## Status

Accepted for this implementation; exact-revision independent review and scoped checks are required before publication.

## Context

The public HNSW index accepts repeated caller IDs as updates. Its forward ID map and current vector were replaced, but obsolete reverse mappings remained searchable. Searches could return an ID twice with its old score; deleting that ID could leave its old version searchable. Removed physical graph rows could also crowd live rows out of a requested top-k. Older serialized snapshots retained the same stale reverse mappings.

## Decision

Invalidate the previous reverse mapping on successful single and batch replacement. Keep the underlying graph's allocated rows and existing binary format. Restore only reverse mappings matching the live vector and canonical forward mapping when loading snapshots.

Hold one read lock while searching. Start with the caller's original k/ef behavior and widen candidate count by bounded doubling when historical positions underfill live results, up to the finite historical `next_idx` count. Return at most min(k, live count) current IDs. This does not turn approximate nearest-neighbor search into an exact scan or rebuild.

## Tradeoffs

Replacement/deletion-heavy indexes may traverse substantially more historical graph positions, with a correspondingly larger ef. Worst-case candidate expansion approaches the historical index count, which can exceed the current physical graph size after restoration. This is a termination bound, not a strict current-size memory or latency guarantee. The unchanged physical graph still consumes memory until reconstruction; this change repairs public identity and underfilled retrieval without adding concurrent graph compaction. The read lock freezes mappings during bounded retries.

## Validation

Nine public Rust regressions cover single/batch replacement, deletion after replacement, top-k underfill, current serialization round-trip, a binary snapshot generated by the original source, ordinary/empty/dimension-error controls, sparse-label restore followed by insertion, and a mixed single/batch/delete/re-add/restore lifecycle. The October 26 candidate before integration fails seven cases and passes two controls; the integrated candidate must pass all nine. The original snapshot contains changed@1, changed@100 and keeper@2 and returns changed twice; fixture provenance is recorded in tests/fixtures/hnsw-legacy-replacement.md. Scoped fixed tests and broader checks are recorded separately before publication; no cross-platform or hosted-CI claim is made.
